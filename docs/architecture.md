# Architecture

## One engine, four products

| Product | What it is | Built in |
|---|---|---|
| GlyVerity Engine | Python library: read mzML, find features, group related ions, assign compositions with q-values, report | Phases 2 to 4 |
| GlyVerity Report | One-page standard output (composition, specificity level, GlyTouCan ID, q-value, artifact flags) aligned with MIRAGE MS v1.0 | Phase 4 |
| GlyVerity Bench | Versioned ground-truth sets that any tool can be scored against | Seeded in Phase 3; long term |
| GlyVerity Atlas | Versioned reprocessing of public glycomics data, refreshed each quarter | Long term |

## Pipeline

1. **Read**: mzML via pyOpenMS (optional dependency `glyverity[ms]`).
2. **Features**: LC-MS feature finding (OpenMS) or import from LC-MS Data Processor.
3. **Clean**: evidence layers group features that are isotopes, adducts, in-source fragments or
   label side-products of another feature. Each grouping is recorded, never silently dropped.
4. **Assign**: target and decoy compositions are matched to the remaining features; scores are
   combined across evidence layers; q-values are computed per composition.
5. **Report**: specificity level (composition, topology, linkage), GlyTouCan ID where one exists,
   q-value, artifact flags, MIRAGE fields.

## Evidence layers (plugins)

Each layer subclasses `glyverity.evidence.EvidenceLayer`, has a name and version, and is
registered with `@register`. Planned layers, in order:

| Layer | Phase |
|---|---|
| isotope pattern | 2 |
| adduct and charge grouping | 2 |
| label side-products and label-solvent adducts | 2 |
| in-source fragments (co-elution and mass difference) | 2 |
| retention consistency (GU or dextran ladder) | 3 |
| ion mobility CCS consistency | later |
| biosynthetic feasibility (glycowork) | later |

## Scope guard

PhD-stage scope is released-glycan LC-MS. Glycopeptides, HMOs, glycolipids and GAGs are
later versions. Any proposal outside scope goes to `docs/roadmap_later.md`, not into code.

## Reproducibility rules

* Every number in a paper comes from a script in `scripts/` run on files listed in
  `data/catalog/datasets.csv`.
* Every figure is regenerated by a script.
* Every dataset's licence is recorded before reuse.
